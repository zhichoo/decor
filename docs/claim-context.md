# dev0.2 来源观点与证据

## 开发范围

`dev0.1` 保留已发布版本；`dev0.2` 实现来源观点结构、提示词、证据保存、卡片表达与歧义不收录。人工和 AI 二次审批已移除。不增加按需局限性分析、外部搜索或个人推荐分数，不自动重提取现有知识，不自动更新线上静态站。

## 字段与边界

- `author_stance`：赞成、反对、中性陈述、未明确，仅记录作者态度，不代表系统推荐。
- `content_type`：选购建议、施工做法、验收要求、价格信息、个人体验、中性说明、其他，记录主要类型，不代替态度。
- `conditions`：仅保存文案明确提出的适用条件；缺失时保持“未提及”。不要求填满户型、地域、预算、风格，背景也不自动构成适用限制。
- `source_quotes`：1 至 3 段文案中逐字匹配的连续引句；不润色、不拼接，用于核对来源，不证明作者说法正确。
- `field_evidence`：正式保存每个非空知识字段对应的引句索引；理由、替代方案按最终数组下标绑定。可选字段剔除后同步重排字段和引句索引。
- `source_scope` / `scope_quote`：正式保存一般陈述、案例、个人体验、比较范围及范围引句。一般陈述不代表普遍真理；非一般范围要求逐字证据。
- `evidence_contract`：正式证据绑定所使用的内部契约版本，当前为 v11；不是提示词版本或模型输出协议版本。
- `stance`：保留旧 API/数据库兼容；新赞成、反对分别映射明确推荐、明确不推荐，中性陈述和未明确映射未明确。旧版有条件、价格建议不推断推荐方向。

卡片继续通过已有 `extraction_run_id` 关联运行的 `input_hash`、`prompt_version`、模型和原始响应，不复制一套独立版本。新证据入库前要求运行属于同一视频、文案哈希一致、提示词版本非空；不合法时在替换旧卡前拒绝。旧卡新字段保持 NULL，不靠迁移推断或补写。新增追溯字段暂不进入公开 API 卡片和静态快照，不扩充前台布局。

新提示词要求保留个人体验和比较范围，不能把自家经历概括成普遍禁忌，也不能推导反命题。缺少完整背景不单独作为过滤理由。格式、枚举、引用和数字校验不等于语义事实核验；在小样本文案上人工验收后，才能评估模型是否忠实保留了范围。

v7 小样本复测收紧数字校验：数字必须出现在该卡的引句中，不能借用整篇文案其他对象的数字修补含糊 ASR。提示词补充报价案例服务约定、酒店观察范围和对象/态度方向一致性规则。这仍不能证明数字与对象关系正确，也不会自动识别所有转写错误；含糊参数需要回看原视频确认，不以模型猜测替代。

## 当前提取逻辑与观察维度

自动流程先获取文案、识别推广，只有明确非推广才自动提取；管理员显式提取可以单独触发。模型按独立决策或施工问题拆卡，过滤推广相关主张、纯品牌清单、空泛评价、无可复用知识的展示和无法理解的内容。之后程序校验类型、枚举、结论、引句与数字，再分流为正式观点或不收录项，不产生待审批任务。

当前观察维度是作者态度、内容类型、装修阶段、空间/主题标签、来源结论、作者理由、明确条件、价格、替代方案、个人/案例范围与逐字引句。户型、地域、预算、风格不是必填观察矩阵；原文未说明就不生成，不把来源提取变成系统推荐。程序检查“是否有文字依据”，不等于核验作者说法、规范或 ASR 正确性。

## v9 保守筛选：移除二次审批

- **当次筛选**：模型仍可通过兼容字段 `review_issues` / `ambiguities` 描述歧义；它们现在只是不收录原因，不是审批候选。模型指出疑点或程序发现本卡参数断裂、已知高风险转写、数字无本卡引句支持时，相关主张不进入正式卡片。缺少未说出的预算、地域等维度不算歧义。
- **不猜测**：引句必须来自原文；伪造歧义引句、无效格式和技术失败仍使本次提取失败并保留已有卡片，不能伪装成筛选成功。规则词表只是有限信号，不代表检测全部语义错误或事实核查。
- **记录**：复用 `extraction_runs.review_data` 记录必要的不收录原因和证据，状态为 `excluded`，不保存可批准恢复的候选。历史记录保留，输入哈希与 superseded 继续用于判断当前结果。
- **成功替换**：明确重提取且输出有效时，清楚观点正常替换入库；全部存疑返回 `filtered`，该视频旧正式卡软删除、文案保留。模型超时、解析失败、证据输出不合法时不会清空旧卡。写卡、记录排除项与更新视频状态在同一事务内。
- **无审批**：独立质量复核菜单、冻结样本工作区页面与 API、视频详情候选确认和舍弃 UI、候选批准后端实现均移除；旧 `/api/admin/quality` 和 `/api/videos/:id/reviews...` 返回 410，不能通过旧请求确认入库。没有 AI 二次审批。
- **进度**：只显示清楚观点入库和存疑未收录，不把它们作为待审批任务。旧 pending 历史按不收录处理，不改写历史，也不反复自动付费提取；原文改变后旧排除结果不再适用。一次正常过滤后，新的技术失败不能被旧过滤状态遮住。
- **补救**：需要挽救特别有价值的片段，只能主动修正文案再提取，没有勾选放行的旁路。普通文案编辑和推广标记修正仍是管理功能，不属于第二轮入库审批。
- **隐私**：不收录诊断与提取历史仅管理员可读，不进入公共缓存和静态快照；公开产物仍只包含正式卡片的允许字段。

离线冻结、抽样、报告脚本保留供开发验证，不是业务审批，也不代表真实内容已通过人工标注。当前引句没有可靠音频时间戳，不提供伪造的精确跳转。

2026-10-30 已对正式库只读盘点，并用官方模型对 8 条现有文案完成 v9 文件化试验。发现案例范围丢失、顶层歧义与保留结论矛盾、推广卖点仍被提取、重复拆卡和关键词误过滤，尚不具备全库替换条件。正式内容未改写；详情及版本数量见 [版本盘点与小批验证报告](../md/claim-upgrade-audit-20261030.md)。本次开发抽检不构成新的业务审批。

## v10 来源边界与同组复测

`extract_claims_v10_source_boundaries` 在同次响应增加推广主体、来源范围、范围证据、卡片临时编号和歧义关联。实际提取与试验工具要求同一严格契约；推广相关或关系不明的主张不收录，明确关联的歧义阻断对应卡片。案例、个人和比较结论保留归属，价格补出作者报价归属；相同内容去重，清楚施工建议不只依赖关键词白名单。临时字段不扩展公开卡片字段或数据库结构。

同组 8 条文案真实复测，候选由 v9 的 38 个变为 28 个，两条推广对照均为 0。但含糊参数、跨卡片歧义依赖和引句覆盖仍有问题，**验收未通过，不执行全库覆盖**。没有新增二次审批。样本、用量及剩余问题见 [v10 复测报告](../md/claim-upgrade-v10-trial-20261030.md)。不能把模型填对结构等同于语义保真。

## v11 字段证据依赖

`extract_claims_v11_field_dependencies` 要求对象、结论、每条理由、条件、替代方案和价格分别绑定卡片引句，字段数字不能借用其他字段的引句。当前响应内已定位的疑点术语跨卡片联动，防止删除做法卡后继续保留依赖同一疑点的原因卡；有限的材料尺寸规则检查数值含义缺失。明确可分离的价格、理由、替代方案字段校验失败时清除该字段，核心结论或条件失败则整卡舍弃，不自动扩宽范围。

原组 8 条真实调用后，又用相同保存响应离线验证可选字段清理，没有追加付费调用。最终 15 个私有候选，含糊尺寸已被阻断，清楚预算方案未因附加价格被误舍弃；但仍有字段绑定不能证明完整语义覆盖、两条响应格式失败。**尚未通过全库覆盖门槛，正式内容未改写**。具体边界、用量及复算方式见 [v11 复测报告](../md/claim-upgrade-v11-trial-20261102.md)。没有新增审批或打分。

## v12 直接证据对

v12 阶段提示词为 `extract_claims_v12_direct_evidence`。模型使用 `statement: {text, quote}` 等直接证据对，由 `claim_wire.py` 生成临时卡片编号和字段证据索引，再进入原有内部 v11 校验。实际提取要求新协议；旧协议、混合格式和非逐字引句失败时保留旧卡，不会自动改证据。每卡最多 3 段不同引句、可选字段清理和核心条件保护仍保留。这是输出协议简化，不是新的语义核验或审批机制。

原组 8 次真实调用得到 8 个私有候选，3 条有候选、3 条过滤、2 条校验失败。两条推广对照仍为 0，但仍有无效 JSON、改动原文换行、结论超出引句及泛泛管理表述。**验收仍未通过，未启动未见样本或全库覆盖，正式业务数据签名不变。** 详见 [v12 复测报告](../md/claim-upgrade-v12-trial-20261102.md)。下一步考虑程序生成文案片段编号以减少证据复制错误，不将有效引用误认为完整语义支持。

## P1 安全修复与全库检查

P1 阶段提示词为 `extract_claims_v13_safety_guards`，当时输出格式为 v12、内部契约为 v11。短文案不再按 120 字直接执行零卡替换；不足以提取的输入报错并保留旧卡。新增有限的明确条件保留检查、数量单位/量纲/参数角色及单价口径检查，并修复无具体术语的短范围疑点关联。转写术语依赖仍避免把长引句里的不相关噪声传播到清楚预算方案。该阶段没有新增审批、评分或数据库列。

全库只读检查覆盖 872 条记录、779 张有效卡，93 条删除记录未恢复。402 张从匹配历史响应找回引句供检查，全部旧卡仍缺正式字段级证据绑定；157 张命中需优先核对提示，其中数字类 76 张、推广来源类 89 张、重叠 8 张。这不是确认错误数，其他卡也没有获得通过证明。新模型调用和正式写入均为 0，前后业务数据签名一致。具体边界、测试和逐卡私有结果位置见 [P1 修复与全库检查报告](../md/claim-p1-fixes-and-full-audit-20261102.md)。原组保存响应离线复算仍有 2 条校验失败，未放开全库覆盖。

条件充分时可以提供有来源依据的装修建议；这与来源提取和审批不同。多维条件比较与评分范围见 [V2 范围重估](../md/v2-scope-reassessment.md)，本批不实现推荐页面或统一总分。

## 正式证据持久化

2026-11-02 在 P1 修复之后补齐上述四个可空字段，更新新库基线、两条增量迁移路径和就绪检查。正式写入保存的是通过筛选、可选字段清理、索引重排及范围归属补充后的卡片；不只保留模型最初输出的绑定。

全库检查优先验证卡片已存的证据及运行关联，不依赖原始模型响应才能检查新卡。已存绑定损坏时记录问题，不用历史响应静默覆盖；文案已变化、运行属于其他视频或缺版本时不视为有效字段证据。旧卡仍可按原有严格匹配条件恢复历史引句供只读检查。升级盘点不再仅凭提示词版本和有引句就判定为当前结构，还要求完整、有效的已存证据和来源范围。

本轮未执行正式库迁移、重提取、部署或静态发布，没有新增模型调用。证据可追溯只解决“依据在哪里”，不证明该引句完整支持结论，也不证明作者说得对。原组无效 JSON、复制引句换行、语义覆盖和低信息问题仍需后续验证。实施及测试记录见 [证据持久化记录](../md/claim-evidence-persistence-20261102.md)。

## v14/v15 片段编号试验

该轮最终提示词为 `extract_claims_v15_segment_ids_only`，模型输出协议为 v14，内部及正式证据契约继续为 v11。程序按原文标点/换行切分，长片段不超过120字；偏移仅留在程序内，模型只看到 `id` 和 `text`。结论、条件、价格使用 `[文本, 起始编号, 结束编号]`，程序按原始偏移取连续证据，最多8段/480字且每卡最多3个不同引句。不重新拼接、润色或纠正原文。范围、推广主体及疑点也使用编号；标题仅可作为推广背景 `[0,0]`。

旧 v12 直接引句仅能用于历史响应的离线读取，新提取不能降级绕过编号协议。无效编号、过长证据、不合法疑点或混合协议使当次失败并保留旧卡，不修补。模型正文必须完整为一个 JSON 值，不再从解释、代码围栏或不完整正文中截取看似完整的子对象。

原组两轮共16次官方模型调用，第一轮 v14 提示有6条协议失败；移除字符偏移并明确空值后，v15 提示为5条有候选、1条成功过滤、2条校验失败。后续补充有限的“如果…那么/就会/会…”陈述性前提检查，使用保存响应离线重算排除1张漏前提卡，剩43个私有候选。**仍未通过升级门槛。** 条件、转写歧义与结论的依赖、价格组成范围、长引句和重复拆卡尚有缺口，不能把43张当作已验收结果。没有新增审批、评分、正式写入或部署，未启动未见样本。详情见 [片段编号复测报告](../md/claim-upgrade-v14-v15-trial-20261102.md)。

## v16 疑点来源依赖与取舍边界

该轮提示词为 `extract_claims_v16_source_dependencies`，模型输出协议为 v16，内部及正式证据契约仍为 v11。旧 v12/v14 响应仅能显式离线读取。片段切分方式、证据长度和卡片数量上限不变。

疑点区分 `blocking=source`（核心动作、参数或范围不明）与 `blocking=terms`（不影响独立主张的局部词项不明）。程序从片段编号生成不可由模型填写的原文偏移，把字段与疑点来源的重叠用于阻断依赖；删除或换写疑点词不能解除 source 依赖。可分离的理由、价格和替代方案可以清理，核心结论或条件不可靠则不收录。偏移为本次校验的临时元数据，不增加公开卡片字段。

新增有限的局部代价保留和报价小计组成检查：原文明说的露边等代价须随方案保留；不能删去价格组成后仍保留整组小计，也不能替作者重算不一致的账。这些规则不覆盖任意中文语义、全部价格表达或对象与价格关系。

原组8条真实调用首次全部通过格式校验：6条产生44张私有候选，2条推广对照成功过滤。四等分预算去重、橱柜露边代价、推广证据长度有所改善；但仍出现损坏工艺词被推测补全、报价范围遗漏及整段疑点误伤清楚施工顺序。模型还将一处核心参数疑点标为 terms，当前样本因保留了该词而被阻断，并不证明这种误分类下的改写也安全。**内容验收未通过，不启动未见样本或全库替换。** 正式业务数据签名不变，无迁移、重启或发布。详情见 [v16 复测报告](../md/claim-upgrade-v16-trial-20261102.md)。

## v17 短句证据与原词删减试验

该轮开发候选提示词为 `extract_claims_v17_source_clauses`，模型输出协议为 v17，内部/正式证据契约仍为 v11。**这是未通过验收的开发实现，不是已发布或可用于全库升级的版本。** 不增加前台字段、数据库列或二次审批。

按逗号等进一步切短句，保留原始字符和偏移，不拆阿拉伯数字内部的千分逗号；最多16个短片段但仍限制480字和每卡3个证据。旧 v14/v16 离线读取固定使用原切分算法及8片段上限，不能用新编号解释旧响应。参数疑点只允许 source 阻断，不允许降为 terms 绕开核心参数依赖。

试验要求知识字段沿用所选原文、按顺序删减。程序通过字符顺序及已有数量归一化检查明显新增/重排，额外检查有限的否定动作；可选字段仍可单独剔除。该检查不等于词义或语义核验，不能防止全部删否定、跨词拼接、抄入损坏文案或标题推测。对象标题暂不受此限制，仍是待验证风险。

补充“……的话”前提保留、同文异位的条件证据定位，以及有限品类的邻近报价尺寸检查。尺寸须与同一地柜/吊柜等对象对应，不能借另一个对象的相同数字通过。忽略“这块的话”等纯指代话题词，不把它当真实条件。这不是任意跨全文的场景推断。

原组8次真实调用：4条产生39张私有候选、1条成功过滤、3条校验失败。之后仅离线修正纯指代条件误报，得到40张候选，没有追加调用。预算方案碎片化、损坏原句照抄、不同短句间同一疑点术语漏关联，以及推广链误判仍存在；**全字段原词删减策略未通过，不能作为已经解决保真问题的默认方案推广。** 未启动未见样本或正式替换，业务签名不变。详见 [v17 试验报告](../md/claim-upgrade-v17-trial-20261102.md)。

## v18 跨句依赖与输出简化

该轮开发候选提示词为 `extract_claims_v18_ambiguity_dependencies`，模型协议 v18，内部/正式证据契约仍为 v11。**该轮原组验收失败，未用于全库升级，也未发布到运行服务。** 不增加审批、评分、数据库列或前台字段。

撤下新输出的全字段删减限制，允许概括清楚口语；保留数字、地点、条件、代价、报价范围及有限的原动作否定检查。标题要求来自结论所选证据的连续原文短语，不能自由猜动作。理由和替代方案各只输出一个三元组或 null，由程序转换为原内部数组；不修补畸形响应。旧 v17 离线读取保留其短句编号及删减标记，旧 v14/v16 仍用原句级编号。

核心疑点同时保留来源偏移和具体术语。程序检查输出字段及其绑定证据里的同一疑点词，跨句联动，不让概括删词解除依赖。局部 terms 疑点仍仅按输出文字关联，避免材料清单噪声误伤独立预算。短标题也不能绕开价格尺寸检查：判断对象同时查看结论和结论证据。上述都是有限保护，不等于识别全部损坏文案或核实语义。

非浏览器回归377项，376通过、1跳过。原组一次8次官方调用：3条产生8张私有候选、2条推广合法零卡、3条证据长度/范围失败。“胶浆”跨句依赖已被阻断，但“做泥包贴”未标疑点仍被照抄，预算方案碎片化、概括补出保证、清楚信息误舍弃仍存在。没有追加付费重试、未见样本或全库覆盖，正式数据签名不变。详见 [v18 试验报告](../md/claim-upgrade-v18-trial-20261102.md)。后续先分清文案损坏和知识/证据粒度问题，不再靠叠加格式规则与重复调用推进。

## 收敛策略：失败舍弃，不自动抢救

v18 原组试验之后决定停止扩充提取协议，不为抢救少量卡片继续开发候选证据窗口、增加模型调用或放宽校验。接受部分清楚知识未被提取，核心动作/材料/数字/条件不明仍整卡不收录；理由、价格、替代方案可独立分离时仅清理该字段。没有重新引入审批或评分。这不代表未被识别的转写错误已经解决，也不改变 v18 未通过全库验收的结论。

安全收尾统一为：一次模型调用只提交一次请求，429、503、网络错误、超时、空响应均不自动重试；404也不自动改到 `/v1` 重发。旧 `DEEPSEEK_MAX_RETRIES` 不再启用重试，curl 无法启动时仍可使用 urllib，前者尚未发出请求。请求前写入 `request_started` 运行记录，意外中断导致结果未知时也不自动付费重跑。

自动队列及“下一条提取”按视频与原文哈希排除任何已尝试输入，不再只跳过旧 pending 项；直接自动入口在视频锁内再次检查，避免选中后已有运行仍重复提交。相同文案即使升级提示词也不会自动重试，原文修改后可作为新输入；管理员明确重新提取和完整重试不受该自动排除限制，完整重试仍保留推广检查。使用现有运行记录，无新迁移。

技术失败保持失败并保留旧卡和原文；合法响应中核心存疑项被剔除仍属于正常筛选，两者不能混为一谈。本轮不执行真实模型调用、正式数据更改、服务重启或发布。策略与验证见 [失败舍弃安全收尾](../md/claim-drop-failed-policy-20261102.md)。

## v19 小批实际启用

2026-11-03 提示词收敛为 `extract_claims_v19_compact_grounded`，模型输出继续使用 v18，内部/正式证据契约继续为 v11，不增加评分、审批或知识维度。提示词模板从4683字缩短至2724字；这不是结构上另起一套协议。

- 输入片段新增程序算好的 `allowed_last=[最小结束id,最大结束id]`，提示合法证据范围。片段编号、原文、16段/480字/每卡3引句限制不变，输出错误仍拒绝，不自动拼补引句。该提示没有解决所有格式失败。
- 标题允许取自其绑定原文或已经写出的结论，不再仅因“预算开分成”与“预算分成”的表达差异丢弃清楚主张。标题不能增加正文和证据中都没有的动作；数字和其他字段仍单独校验。这提高可用性，不等于能验证任意概括的语义。
- 对“占25”缺单位、已确认的“做泥包贴”、混写金额“四5万”、超出所选证据的保证语气，以及只有“重新找平费用高”的空泛碎片增加有限保护。没有把这些规则当成通用文案纠错或事实核验。
- 同组8条各调用一次官方模型，无重试。最终复算3条非推广视频可采用，共6张候选；3条普通样本格式失败，2条推广对照均不采用，其中一条仍有推广链漏滤。**不满足全库升级条件，不以少提取或合法字段宣称整体质量过关。**
- 备份、兼容迁移并重启本机服务后，仅将3条已核对的非推广视频写入正式库。6张新卡替换6张旧卡，旧卡系统软删除归档；原有手动删除、其他视频和推广卡不变。应用保存响应时不再调用模型，按当前文案、提示版本、旧卡内容和删除保护重新检查；事务失败回滚，重复执行跳过已完成项。
- 知识库异步刷新保留当前历史条目的展开状态；返回时搜索尚未完成，待真实结果到达再恢复阅读位置。只保存卡片ID和阅读状态，不缓存旧卡内容来覆盖新数据。

实际启用只发生在本机服务，Cloudflare 公开站仍是原静态快照。详细结果及边界见 [小批启用记录](../md/dev02-v19-small-batch-release-20261103.md)。

## 兼容与发布

开发环境及 Docker 启动时自动执行可重复的增量迁移，仅添加可空字段。旧观点不重写；缺引句时显示“暂无引句”，缺少内容类型统一显示“未分类”，不与提取版本绑定。已有旧格式提取结果仍可读取，不将其冒充完整的新结构。

Git 分支只隔离代码，不隔离数据库、浏览器登录态或正在运行的 Python 进程。切换分支后，已有服务不会自动重载后端；确认数据库备份和环境后，使用 `./dev.sh stop`、`./dev.sh start` 重启，或在独立目录和独立数据库中试用。迁移本身不会重提取或更改已有卡片，新字段也兼容旧版代码读取；不要通过删除字段来回退分支。

知识库、视频详情和观点浮窗共用卡片组件。作者态度使用中性样式，避免绿色/红色平台评级；已有明确条件才显示条件，不铺满空字段。作者态度和内容类型可分别筛选，统计始终基于全库。

静态导出同步保留新字段及筛选，但仍没有登录、修改、删除、提取功能。真实数据不会随分支推送；试验默认只对已有文案生成私有文件。明确的小批写入使用 `scripts/apply_claim_upgrade.py`，默认预检，带 `--execute-database-writes` 才执行，不能把未知或推广来源当普通升级应用；这不执行 `publish-public.sh` 发布线上快照。
