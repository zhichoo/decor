# dev0.2 来源观点与证据

## 开发范围

`dev0.1` 保留已发布版本；`dev0.2` 先实现来源观点结构、提示词、证据保存和卡片表达。不增加按需局限性分析、外部搜索或个人推荐分数，不自动重提取现有知识，不自动更新线上静态站。

## 字段与边界

- `author_stance`：赞成、反对、中性陈述、未明确，仅记录作者态度，不代表系统推荐。
- `content_type`：选购建议、施工做法、验收要求、价格信息、个人体验、中性说明、其他，记录主要类型，不代替态度。
- `conditions`：仅保存文案明确提出的适用条件；缺失时保持“未提及”。不要求填满户型、地域、预算、风格，背景也不自动构成适用限制。
- `source_quotes`：1 至 3 段文案中逐字匹配的连续引句；不润色、不拼接，用于核对来源，不证明作者说法正确。
- `stance`：保留旧 API/数据库兼容；新赞成、反对分别映射明确推荐、明确不推荐，中性陈述和未明确映射未明确。旧版有条件、价格建议不推断推荐方向。

新提示词要求保留个人体验和比较范围，不能把自家经历概括成普遍禁忌，也不能推导反命题。缺少完整背景不单独作为过滤理由。格式、枚举、引用和数字校验不等于语义事实核验；在小样本文案上人工验收后，才能评估模型是否忠实保留了范围。

## 兼容与发布

开发环境及 Docker 启动时自动执行可重复的增量迁移，仅添加可空字段。旧观点不重写；缺引句时显示“旧版提取，暂缺卡片级引句”，旧内容类型显示“旧版未分类”。已有旧格式提取结果仍可读取，不将其冒充完整的新结构。

Git 分支只隔离代码，不隔离数据库、浏览器登录态或正在运行的 Python 进程。切换分支后，已有服务不会自动重载后端；确认数据库备份和环境后，使用 `./dev.sh stop`、`./dev.sh start` 重启，或在独立目录和独立数据库中试用。迁移本身不会重提取或更改已有卡片，新字段也兼容旧版代码读取；不要通过删除字段来回退分支。

知识库、视频详情和观点浮窗共用卡片组件。作者态度使用中性样式，避免绿色/红色平台评级；已有明确条件才显示条件，不铺满空字段。作者态度和内容类型可分别筛选，统计始终基于全库。

静态导出同步保留新字段及筛选，但仍没有登录、修改、删除、提取功能。真实数据不会随分支推送；不在本次开发中调用模型处理生产内容，也不执行 `publish-public.sh` 发布线上快照。
