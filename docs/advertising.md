# 软性推广识别

文案获取或人工保存后，使用当前 `DEEPSEEK_*` 配置单独识别推广。这个调用只做分类，
不生成观点；本地 ASR 仍只负责语音识别，推广分类需要联网并消耗模型额度。

识别标准参考现有文案的实际结构，而非促销关键词：

- 科普铺垫：先讲选购标准，再将具体产品包装成满足所有条件的答案。
- 故事植入：先讲装修设计或家庭故事，再集中介绍单款产品的参数和卖点。
- 选购矩阵：将同品牌多个型号按预算、空间、使用场景逐一推荐。
- 导购推广：团购、直播、粉丝群低价及促销产品清单。

提到品牌、型号、价格，或结尾求关注，本身不构成推广。普通施工细节、预算表、
多品牌举例及有真实局限的客观测评应与推广区分。标签表示内容具有推广特征，
不表示已证实作者接受商业报酬。当前使用样本归纳后的提示词，不是模型微调。

## 结果与安全边界

`videos.ad_review` 保存判断、理由、原句证据、规则版本、输入哈希和时间。
“推广”至少需要两条不同的原文/标题引用；伪造引用或无效输出不予确认。
标题占位文案不送模型猜测。修改文案后旧结论失效，新结果不会覆盖处理中被人工修改的文案。

- `advertising`：页面显示“推广”，跳过自动观点提取。
- `not_ad`：允许原有自动提取流程继续。
- `uncertain` / `error`：显示“疑似推广”，暂不自动提取。
- 无文案：仍待获取文案，不因尚未识别而停止转写。

自动队列、快捷入库附带提取、从文案开始的整条重试，以及“提取下一条”均遵循此检查。
管理员仍可明确点击单个视频的“提取观点”。推广识别不会删除历史文案、观点或提取记录。
判定结果按输入缓存，获取已有文案不会重复识别；服务错误可在下次操作中重试。

## 手动修改状态

管理员登录后，在“视频详情 → 推广状态”选择“普通内容 / 疑似推广 / 推广”，点击“保存状态”。
手动结果单独保存到 `videos.ad_review_override`，优先于自动识别；修改标题、文案或后续重新识别不会覆盖它。
选择“自动识别”并保存可清除手动设置，恢复有效的自动识别缓存；无有效缓存时下次获取或保存文案再识别，不会立即调用模型。
保存状态本身不提取观点，也不删除知识卡。“推广”会让来源知识卡显示“来源视频标记为推广”；改为其他状态后提示消失。
“普通内容”允许后续自动队列提取；“疑似推广”和“推广”阻止自动观点提取，但不阻止获取缺失文案。

## 批量补齐与回审

```bash
.venv/bin/python scripts/review_video_ads.py --review-existing
.venv/bin/python scripts/review_video_ads.py --backfill --include-placeholders
```

第二条只补空文案及“文案等于标题”的占位记录，获取成功前保留原文案；
沿用当前选择的转写方式，不自动切换到付费转写，也不提取观点。
失败逐条记录后继续，已有外部待核对任务仍受原有任务账本约束。
记录与私有文案快照位于 Git 忽略的 `.runtime/ad-review/`，不要提交这些真实数据。
浏览器下载仅支持现有抖音视频入口，登录、风控或视频失效仍可能导致部分补齐失败。

已有数据库运行 `scripts/migrate_transcript_jobs.py` 增加 nullable `ad_review`、`ad_review_override` 列；
`./dev.sh start` 会自动执行该增量迁移，不重建业务表。
